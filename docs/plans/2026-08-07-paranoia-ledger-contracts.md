# Paranoia, Ledger, Contracts — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add three coupled features to TrapCraft — Paranoia (packet-only hallucinations driven by Heat), The Ledger (a chest-search item), and Contracts (generated delivery jobs) — all server-side, all craftable, all with real models and live feedback.

**Architecture:** One shared `TrapPhantom` utility sends per-player lies (fake blocks, positioned sounds, particles, phantom entities) and guarantees they are always reverted. `TrapParanoia` reads `TrapHeat` and drives tiered illusions through it. `TrapContracts` generates village deliveries that raise Heat, which in turn raises Paranoia. The Ledger reuses `TrapPhantom`'s particle path for its search pings. No new blocks — the Polymer blockstate pools are nearly dry.

**Tech Stack:** Fabric 1.21.8, Yarn mappings, Polymer 0.13.13, Java 21. Assets generated by `tools/gen_textures.py` and `tools/gen_assets.py`. Verification by `./gradlew build`, the existing `tools/check_*.py` offline checks, and a new minimal JUnit suite for pure math.

## Task 2: `TrapPhantom` — fake blocks and the revert guarantee

The load-bearing safety class. If this leaks, players see permanently wrong blocks and think the world corrupted.

**Files:**
- Create: `src/main/java/dev/heezq/trapcraft/TrapPhantom.java`
- Modify: `src/main/java/dev/heezq/trapcraft/TrapCraft.java` (register lifecycle hooks)

**Step 1: Write the class**

```java
package dev.heezq.trapcraft;

import net.minecraft.block.BlockState;
import net.minecraft.network.packet.s2c.play.BlockUpdateS2CPacket;
import net.minecraft.network.packet.s2c.play.EntitiesDestroyS2CPacket;
import net.minecraft.server.network.ServerPlayerEntity;
import net.minecraft.util.math.BlockPos;

import java.util.*;

/**
 * Show one player something that isn't there.
 *
 * The world is never modified -- every fake block is a render lie sent to a
 * single client. That only stays true because every lie is tracked and
 * reverted: on expiry, on disconnect, on death, on dimension change, and on
 * server stop. A leaked fake block looks exactly like world corruption to the
 * player it's stuck on, which is why the bookkeeping lives here and not in the
 * features that call it.
 */
public final class TrapPhantom {
    /** Fake entity ids count down from here, far below any real entity id. */
    private static final int ID_FLOOR = -2_000_000;
    private static int nextId = ID_FLOOR;

    private record Lie(BlockPos pos, long expiresAtTick) {}

    private static final Map<UUID, List<Lie>> BLOCKS = new HashMap<>();
    private static final Map<UUID, Set<Integer>> FIGURES = new HashMap<>();

    private TrapPhantom() {
    }

    /** Render `state` at `pos` for this player only, reverting after `ticks`. */
    public static void fakeBlock(ServerPlayerEntity player, BlockPos pos, BlockState state, int ticks) {
        player.networkHandler.sendPacket(new BlockUpdateS2CPacket(pos, state));
        BLOCKS.computeIfAbsent(player.getUuid(), k -> new ArrayList<>())
                .add(new Lie(pos.toImmutable(), player.getWorld().getTime() + ticks));
    }

    /** Send the real state back, cancelling one lie. */
    private static void revert(ServerPlayerEntity player, BlockPos pos) {
        player.networkHandler.sendPacket(
                new BlockUpdateS2CPacket(pos, player.getWorld().getBlockState(pos)));
    }

    /** Called every server tick: expire what's due. */
    public static void tick(ServerPlayerEntity player) {
        List<Lie> lies = BLOCKS.get(player.getUuid());
        if (lies == null || lies.isEmpty()) {
            return;
        }
        long now = player.getWorld().getTime();
        lies.removeIf(lie -> {
            if (now < lie.expiresAtTick()) {
                return false;
            }
            revert(player, lie.pos());
            return true;
        });
    }

    /** Reserve an entity id that can never collide with a real entity. */
    public static synchronized int reserveId() {
        return nextId--;
    }

    public static void trackFigure(ServerPlayerEntity player, int id) {
        FIGURES.computeIfAbsent(player.getUuid(), k -> new HashSet<>()).add(id);
    }

    public static void clearFigure(ServerPlayerEntity player, int id) {
        Set<Integer> ids = FIGURES.get(player.getUuid());
        if (ids != null && ids.remove(id)) {
            player.networkHandler.sendPacket(new EntitiesDestroyS2CPacket(id));
        }
    }

    /** Everything, for one player. Safe to call when there is nothing to clear. */
    public static void clearAll(ServerPlayerEntity player) {
        List<Lie> lies = BLOCKS.remove(player.getUuid());
        if (lies != null) {
            lies.forEach(lie -> revert(player, lie.pos()));
        }
        Set<Integer> ids = FIGURES.remove(player.getUuid());
        if (ids != null && !ids.isEmpty()) {
            player.networkHandler.sendPacket(new EntitiesDestroyS2CPacket(
                    ids.stream().mapToInt(Integer::intValue).toArray()));
        }
    }

    /** Drop state without sending packets -- for a player already gone. */
    public static void forget(UUID player) {
        BLOCKS.remove(player);
        FIGURES.remove(player);
    }
}
```

**Step 2: Wire the lifecycle in `TrapCraft.java`**

```java
ServerTickEvents.END_SERVER_TICK.register(server ->
        server.getPlayerManager().getPlayerList().forEach(TrapPhantom::tick));
ServerPlayConnectionEvents.DISCONNECT.register((handler, server) ->
        TrapPhantom.forget(handler.getPlayer().getUuid()));
ServerPlayerEvents.AFTER_RESPAWN.register((old, updated, alive) ->
        TrapPhantom.forget(updated.getUuid()));
ServerWorldEvents.UNLOAD.register((server, world) ->
        server.getPlayerManager().getPlayerList().forEach(TrapPhantom::clearAll));
```

`forget` rather than `clearAll` on disconnect: the connection is already closing, so sending revert packets is pointless and may throw. On respawn the client reloads chunks anyway, so the lies are gone visually and only the bookkeeping needs dropping.

## Task 3: `TrapPhantom` — sound, particles, figures

**Files:**
- Modify: `src/main/java/dev/heezq/trapcraft/TrapPhantom.java`

**Step 1: Add the three senders**

```java
    /** A sound only this player hears, at a position they didn't expect. */
    public static void sound(ServerPlayerEntity player, Vec3d pos,
                             RegistryEntry<SoundEvent> event, float volume, float pitch) {
        player.networkHandler.sendPacket(new PlaySoundS2CPacket(
                event, SoundCategory.AMBIENT, pos.x, pos.y, pos.z,
                volume, pitch, player.getWorld().getRandom().nextLong()));
    }

    /** Particles only this player sees. */
    public static void particles(ServerPlayerEntity player, ParticleEffect effect,
                                 Vec3d pos, int count, double spread, double speed) {
        player.getWorld().spawnParticles(player, effect, true, false,
                pos.x, pos.y, pos.z, count, spread, spread, spread, speed);
    }

    /**
     * A figure standing where nothing stands. Returns its id so the caller can
     * remove it; the caller MUST, or it lingers until the player relogs.
     */
    public static int figure(ServerPlayerEntity player, EntityType<?> type, Vec3d pos, float yaw) {
        int id = reserveId();
        player.networkHandler.sendPacket(new EntitySpawnS2CPacket(
                id, UUID.randomUUID(), pos.x, pos.y, pos.z,
                0.0F, yaw, type, 0, Vec3d.ZERO, 0.0));
        trackFigure(player, id);
        return id;
    }
```

Note the `spawnParticles` overload takes `force` and `important` booleans before the coordinates — `true, false` means "send even if far" but "not a critical effect".

**Step 3: Implement the pure function**

```java
    /**
     * How hard the world is pressing on you right now, 0..1.
     *
     * Heat is the dominant term on purpose: this is a mechanic about running a
     * grow op, not about being high. Being high multiplies what's already
     * there rather than adding to it, so a stoned player with no heat and
     * company stays calm -- which is what makes the heat coupling readable
     * instead of feeling random.
     */
    public static float pressure(int heatTier, int highAmplifier, int light,
                                 boolean night, boolean alone) {
        float base = heatTier / (float) TrapHeat.THRESHOLDS.length;   // 0..1
        float dark = light < 7 ? 0.20f : 0.0f;
        float nocturnal = night ? 0.10f : 0.0f;
        float solitude = alone ? 0.15f : -0.20f;                       // company subtracts
        float high = 1.0f + highAmplifier * 0.35f;                     // multiplier

        float raw = (base + dark + nocturnal + solitude) * high;
        return Math.max(0.0f, Math.min(1.0f, raw));
    }
```

## Task 6: Paranoia tier effects

**Files:**
- Modify: `src/main/java/dev/heezq/trapcraft/TrapParanoia.java`

Each tier fires on a random interval, not a fixed one — a predictable scare stops being a scare.

**Tier 1 — behind you.** Pick a point 4–8 blocks behind the player's facing, `TrapPhantom.sound` with `BLOCK_WOODEN_DOOR_CREAK`, `ENTITY_ITEM_FRAME_BREAK`, or `BLOCK_CHEST_OPEN` at low volume.

**Tier 2 — followed.** Buffer the player's position from 10 ticks ago and play `ENTITY_PLAYER_STEP` there whenever they move. Occasional `ParticleTypes.FLAME` at head height where no light source exists.

**Tier 3 — seeing things.** Pick a solid block in view, `TrapPhantom.fakeBlock` it to `Blocks.CHEST` / `Blocks.COBWEB` / `Blocks.ZOMBIE_HEAD` for 15 ticks. Skip blocks the player is standing on or in — a fake block under someone reads as a physics bug, not a hallucination.

**Tier 4 — the figure.** `TrapPhantom.figure` with `EntityType.PILLAGER` at 40–60 blocks, in the player's view cone, motionless. Remove it the moment the player's crosshair comes within ~10° of it or they close within 20 blocks. Rarely, a chat line addressed to the player by name.
