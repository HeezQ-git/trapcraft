# Tourists Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Visitors who are not from the town arrive at the surface above the city vault, run one to three errands (a casino machine, a shop till, a hospital ward), spend outside money that the city taxes, and leave.

**Architecture:** A new `TrapVisitors` owns a list of `Visit` records and one tick loop, in the shape of `TrapFloor.Punter`. It conjures a villager wearing an out-of-town `VillagerType`, walks it errand to errand on `TrapFloor`'s existing step/deadline/doorway ladder, and hands the body to each venue through a seam extracted from that venue's existing "fetch a customer" call. A tourist never receives `TENANT_TAG`, so `TrapHomes.population()` — and therefore rent, payroll, house reputation and the casino's `room()` cap — never counts one.

**Tech Stack:** Java 21, Fabric 1.21.8, Yarn mappings, JUnit 5, Polymer (server-side only — this feature adds no blocks or items and must not consume a Polymer carrier).

**Design:** `docs/plans/2026-08-13-tourists-design.md`

**Step 3: Write the minimum that passes**

Create `TrapVisitors.java` with the tag, the out-of-town types, and the spawn. The variant is a **registry lookup**, not an enum assignment — `VillagerData.withType` takes a `RegistryEntry<VillagerType>` in 1.21.8:

```java
package dev.heezq.trapcraft;

import net.minecraft.entity.EntityType;
import net.minecraft.entity.SpawnReason;
import net.minecraft.entity.passive.VillagerEntity;
import net.minecraft.registry.RegistryKeys;
import net.minecraft.server.world.ServerWorld;
import net.minecraft.util.math.BlockPos;
import net.minecraft.village.VillagerType;
import net.minecraft.world.Heightmap;

/**
 * Somebody who is not from here.
 *
 * Every customer in this mod is a resident, which was the right correction
 * when strangers were a stand-in for a town that did not exist. The town
 * exists now, and the stand-in has become a ceiling: a floor's costs are
 * linear in cabinets and its income is capped by the town, so at fifty-one
 * machines it could not break even at any hour of any day.
 *
 * So this is the one place in the mod allowed to conjure a villager, and it
 * pays for the privilege by never pretending the result lives here.
 */
public final class TrapVisitors {

    /** What marks somebody as passing through. Never TENANT_TAG. */
    public static final String TOURIST_TAG = "trapcraft_tourist";

    /**
     * What they are wearing, against the plains everybody local wears.
     *
     * Chosen over a name tag, a particle or anything custom because a villager
     * type costs no texture, no model and -- the reason it won -- not one
     * Polymer carrier. The pack booted with sixteen left.
     */
    private static final VillagerType[] FROM_AWAY = {
            VillagerType.DESERT, VillagerType.JUNGLE, VillagerType.SAVANNA,
            VillagerType.SNOW, VillagerType.SWAMP, VillagerType.TAIGA,
    };

    /** How far around the vault's column they turn up. */
    private static final int SCATTER = 8;

    /**
     * Where somebody arrives in town.
     *
     * The vault's COLUMN, not the vault: it is guaranteed to exist -- no
     * vault, no city -- which makes it the one anchor that cannot be missing,
     * but it is a hidden thing in a hole and nobody arrives in town by
     * climbing out of the treasury.
     *
     * MOTION_BLOCKING_NO_LEAVES so a treetop is not a pavement, and only ever
     * in a loaded chunk: getTopY on an unloaded one is the mistake TrapHeat
     * already carries a comment about.
     */
    public static BlockPos doorstep(ServerWorld world, BlockPos vault,
                                    net.minecraft.util.math.random.Random random) {
        for (int tries = 0; tries < 12; tries++) {
            int x = vault.getX() + random.nextInt(SCATTER * 2 + 1) - SCATTER;
            int z = vault.getZ() + random.nextInt(SCATTER * 2 + 1) - SCATTER;
            if (!world.isChunkLoaded(x >> 4, z >> 4)) {
                continue;
            }
            BlockPos top = new BlockPos(x,
                    world.getTopY(Heightmap.Type.MOTION_BLOCKING_NO_LEAVES, x, z), z);
            BlockPos spot = TrapSpawn.near(world, top, 6);
            if (spot != null) {
                return spot;
            }
        }
        return null;
    }

    /** Conjure one, dressed as somebody from somewhere else. */
    public static VillagerEntity arrive(ServerWorld world, BlockPos at) {
        VillagerEntity body = EntityType.VILLAGER.create(world, SpawnReason.EVENT);
        if (body == null) {
            return null;
        }
        body.refreshPositionAndAngles(at, world.getRandom().nextFloat() * 360.0F, 0.0F);
        var types = world.getRegistryManager().getOrThrow(RegistryKeys.VILLAGER_TYPE);
        VillagerType worn = FROM_AWAY[world.getRandom().nextInt(FROM_AWAY.length)];
        body.setVillagerData(body.getVillagerData()
                .withType(types.getEntry(types.getRawId(worn)).orElseThrow()));
        body.addCommandTag(TOURIST_TAG);
        world.spawnEntity(body);
        return body;
    }

    private TrapVisitors() {
    }
}
```

> **If `types.getEntry(...)` does not compile:** the registry API around
> `RegistryEntry<VillagerType>` is the one genuinely uncertain call in this
> plan. Verified present: `VillagerType` holds DESERT/JUNGLE/PLAINS/SAVANNA/
> SNOW/SWAMP/TAIGA, and `VillagerData.withType` has two overloads —
> `withType(RegistryEntry<VillagerType>)` and
> `withType(RegistryWrapper.WrapperLookup, VillagerType)`. If the first is
> awkward, use the second. Do **not** guess a third form; check
> `~/.gradle/caches/fabric-loom/1.21.8/net.fabricmc.yarn.1_21_8.1.21.8+build.1-v2/mappings.tiny`.

**Step 3: Implement**

Add to `TrapVisitors`:

- `enum Errand { CASINO, SHOP, WARD }`
- `private static final class Visit { UUID body; ArrayDeque<Errand> itinerary; int purse; long deadline; boolean ill; BlockPos target; }`
- `private static final List<Visit> VISITS = new ArrayList<>();`
- `public static void register()` — a `ServerTickEvents.END_SERVER_TICK` hook running `tick(server)` every tick and `maybeArrive(server)` every `ARRIVE_TICKS` (start at `20 * 15`).
- `tick(server)`: for each visit, if the body is gone → drop the visit; if the current errand is unfinished and the deadline has not passed → `TrapHomes.walkTo(body, target)` re-asserted on a ~20-tick cadence (see `TrapFloor.NUDGE_TICKS` for why it must be re-asserted, not set once); if the deadline passed → teleport to the errand's doorstep once, exactly like `TrapFloor`'s `shownIn`; when the itinerary empties → `leave(world, visit)`.
- `leave(...)`: `body.setAiDisabled(false)`, walk them back toward the vault doorstep, then `body.discard()`.

Mirror `TrapFloor`'s `ServerEntityEvents.ENTITY_LOAD` handler: a villager carrying `TOURIST_TAG` that no live `Visit` knows about is discarded. Their trip ended when the server stopped.

## Task 3: The casino seats somebody who is not a resident

**Files:**
- Modify: `src/main/java/dev/heezq/trapcraft/TrapFloor.java` (`arrive`, ~line 660)
- Modify: `src/main/java/dev/heezq/trapcraft/TrapVisitors.java`

**The refactor.** `TrapFloor.arrive(server, at)` currently picks the body and then does ~60 lines of stake sizing, serving, naming, seat claiming and session bookkeeping. Split it:

```java
// unchanged: picks a resident and hands off
private static void arrive(MinecraftServer server, String at) { ... seat(world, at, resident(world, pos), false); }

/** Everything after somebody has been chosen. Visitors come in here too. */
public static boolean seat(ServerWorld world, String at, VillagerEntity body, boolean visitor) { ... }
```

Inside `seat`, the only behaviour that branches on `visitor`:
- the punter's `Punter` record gains a `visitor` flag;
- `leave()` must call `TrapHomes.stayIn` / `TrapHomes.sendHome` **only when `!visitor`** — for a visitor it returns control to `TrapVisitors`, which owns the body's departure.

`TrapVisitors` runs the CASINO errand by choosing a free wired machine (reuse the `open` selection in `maybeArrive`, extracted or duplicated as a small public `TrapFloor.freeWire(server)`), walking the tourist there, then calling `TrapFloor.seat(world, wire, body, true)`.

## Task 6: Their money is from somewhere else, and the city notices

**Files:**
- Modify: `src/main/java/dev/heezq/trapcraft/TrapVisitors.java`
- Modify: `src/main/java/dev/heezq/trapcraft/TrapCity.java` (duty on visitor spend)

- Purse: 150–600e, drawn low-biased (take the smaller of two rolls, as `punterStake` does), capped under `TrapHouse.covers(...)` so a visitor can never break a vault.
- Spending enters circulation through the `circulate(+n)` path — `TrapMarket.pay` semantics — so the index sees the inflation and prices answer it. Money that appears without the index noticing is silent inflation; this is the safety catch.
- The city takes its duty on every visitor transaction, **including Gaming duty on their stakes, which resident punters do not pay**. Visitors pay the tourist tax; it is the drain welded to the faucet.

**Test:** assert `TrapVisitors.java` references the circulate/pay path and not `collect`/`handOver` (which move money without touching the economy). Commit as `"A visitor's money is money the index has seen"`.
